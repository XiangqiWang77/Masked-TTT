# BABILONG：同一条自蒸馏轨迹上的步数校准

本实验只改变原方法的更新步数。它沿用缓存的 Decision API 选块、选中片段构造的 ICL Teacher、全文 Student、同一份联合更新的请求内 KV 读取状态，以及最终独立解码的选中缓存 Cartridge。基础模型参数和两份原始 KV 不更新；训练目标仍然是 Teacher 到 Student 的 on-policy 前向 KL，没有额外的选中缓存训练损失。

## 对照方式

每题只训练一条轨迹，在基础更新的第 2、4、8 步保存读取状态。若有通过核验的自学小问题，则每个小问题为三个预算分别增加一步；训练路径顺序保持一致。随后释放全文 KV，依次把三个状态物化到同一份独立 prefill 的选中 KV 上，用同一个原问题和生成预算回答。对每题同时记录全文、选中缓存零更新和 ICL Teacher。

这种设计对齐文档、选块、模型和训练轨迹，避免把不同次选块或随机运行混成步数效应。对照还会报告每组新答对与新答错的数量。用于研究的快照有额外内存开销；它们不是最终单个 Cartridge 的组成部分。

## 数据与选择

使用固定的 200 题开发集，包含 50 个来源问题在 8K、16K、32K、64K 下的版本。另留出与开发集来源问题完全不重叠的 800 题，包含另外 200 个来源问题的四种长度。评测答案只用于事后计分，不能进入选块或训练。

每个模型分别选择：4 步或 8 步必须在 200 题开发集上同时超过全文、选中缓存零更新、ICL Teacher 和默认 2 步 Cartridge；若两者都符合，选择准确率较高者，平分时优先选择新答错较少、步数较少者。如果没有符合条件的版本，该模型不进入留出集。学习率开发集已有胜出配置的模型也不重复启动此步数校准。

获得开发集胜出配置后，先冻结步数，再在 800 题留出集验证，不按留出集结果改参数。留出集目标是相对 ICL Teacher 至少提高 3 个百分点，同时超过全文、选中缓存零更新和默认 2 步 Cartridge。200＋800 的总表可以描述全部 1,000 题，但是否达标以独立 800 题为准。

## 执行状态

截至协议建立时，步数校准尚未提交 GPU 作业。只有完成现有学习率开发实验后，才会根据上述条件决定是否提交；这份协议不代表已经观测到步数收益。选块分数复用现有 JSON，不产生新的在线 API 调用。每次分配最多使用一张 GPU，按作业预算续跑；汇总按小时更新。
