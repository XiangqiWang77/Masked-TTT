# Reproducing OLMo-style Query Cartridges

The experiment uses cached Decision API scores and keeps approximately 10% of the chunks. It reserves part of that budget for entity-linked context, rather than taking only the highest-scoring chunks as in the original OLMo run. The frozen selected-context model provides full-vocabulary probabilities on the full-context student's current answer prefix. The same on-policy KL jointly updates selected-position attention gains and low-rank Value coefficients on the full-document path. The trained state is then materialized on an independently prefetched selected cache; full-document KV, source selected KV and request-local training state are released before the formal answer. The inference path uses neither an extra transfer loss nor evaluation answers.

The step study trains one 32-token-rollout trajectory (the original OLMo cap was 8) and measures the 2-, 4- and 8-base-step states. An accepted practice question adds one update, consistently across the checkpoints. The completed 56-case pilot is reused when the study extends to the full 200-case development split, so only 144 additional cases per model are generated. No step is selected from the oversampled 56-case pilot. The pilot's inference runtime remains unchanged; the extension changes only the report's allowed case count. Treat this as an OLMo-style SD variant, not an exact selector or rollout reproduction.

After all 200 development cases are complete and valid, the highest-answer-quality checkpoint is chosen separately for each model. Ties favor fewer new errors relative to selected zero-update, then fewer steps. A model advances only if the chosen checkpoint beats its same-run whole, zero-update selected and ICL Teacher controls. Development labels are used only for this post-generation configuration choice, never within a request. The fixed choice is then evaluated on 800 source-disjoint cases with one GPU job and cached scores. The scheduler is guarded by the shared limit of 12 single-GPU jobs.

The holdout runs exactly the selected number of steps. Before processing real cases, the loaded backbone verifies that the corresponding checkpoint matches a direct run and that the final selected-KV cartridge is physically independent. If the 200-case gate fails, no holdout is submitted for that model; another configuration must be investigated. A completed 200 + 800 report includes question-type accuracy and new-correct/new-wrong counts. The +3-point target is assessed on 792 holdout cases after excluding two previously inspected sources. Earlier aggregate results have been viewed, so this is not a completely blind holdout.

All methods use the same task-aware loose lexical scorer. The original ICL Teacher has an additional generic response-format instruction; the selected-zero and Cartridge comparisons use the same original question format. Artifact memory is reported separately from model memory and construction peak. An hourly continuation advances the stages only when the preceding results are complete and validated.
