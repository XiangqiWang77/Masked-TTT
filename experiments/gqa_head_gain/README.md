# GQA 查询头独立的读取偏置

OLMo-3-7B 的 32 个查询头各对应一个 KV 头；Qwen3-4B 的 32 个查询头共享 8 个 KV 头，GPT-OSS-20B 的 64 个查询头共享 8 个 KV 头。现有实现按 KV 头设置读取偏置，因此 Qwen 和 GPT-OSS 中分别有 4 个和 8 个查询头共享同一个偏置。本实验检验：让同组查询头分别调整证据读取份额，是否能更充分地利用 OLMo 方法的自蒸馏信号。

对于每个 KV 头，把其组内各查询头的 chunk 偏置写入共享 Key 的额外维度；每个 Query 在这些维度上使用对应的独热向量。保留原 softmax scale 后，点积恰好给每个查询头增加它自己的偏置。Value 仍由组内查询头共享，不复制 K/V；低秩 Value 更新、Teacher、全文 Student 和自蒸馏目标均不需要改变。

这只是一个可选择的参数化：将同组偏置设为相同，数学上回到现有实现；全部设为零时回到原始注意力。在 Qwen 的 128 维头和 GPT-OSS 的 64 维头下，增加 4 或 8 个偏置维度后，仍分别填充到 160 或 96 维，和原来补一个偏置维度的缓存张量大小相同。

[实验代码](attention.py)和[测试](../../tests/test_gqa_head_gain.py)在 CPU 上检查了不同分组、attention sink、因果掩码、前向以及 Q/K、偏置和 Value 的梯度，并检查共享偏置与零偏置的等价性。它还没有接入正式 Cartridge 路径，也没有真实模型上的准确率或 GPU 耗时结果；该设计能否改善 Qwen 和 GPT-OSS 的答题质量，需要后续配对实验。
