# BABILONG：同预算关联选块实验

这项实验改进如何使用已保存的 Decision API 分数，不改变 Masked TTT Cartridges 的训练方式。Teacher 仍只读取独立构建的选中 KV，Student 仍在全文 KV 上接受 on-policy Teacher→Student KL；模型参数和原始缓存冻结，最终只用物化后的独立 Cartridge 回答。

## 为什么增加关联选块？

某些回答需要连接两条分散事实。例如，选中的片段包含“Daniel 拿起牛奶”和“Daniel 放下牛奶”，但中间“Daniel 去了花园”可能不含问题中的“牛奶”，因而 Decision 分数较低。漏掉这条连接信息，选中 KV 就缺少确定最终位置所需的上下文。

实验保持相同的 **10% 选块数**：先用 Decision 分数保留约四分之三的高分块，再利用这些块中与问题同句出现的实体名称，在剩余块中寻找相关上下文；剩余名额仍按 Decision 分数补齐。关联排序使用实体出现频率和与高分块的距离，最终块按原文顺序排列。代码只使用文档、问题和缓存分数，不读取答案或支持事实标注，也不调用在线 API。当前名称提取是面向英文的简单启发式，不宣称对所有语言或文档都适用。

## 开发集观察

在固定 200 题开发集（50 个源问题、每题四种长度）上，按原始任务的支持事实标注做事后覆盖检查：

| 策略 | 实际选中块比例 | 全部标注事实覆盖 | 相对原选块：新覆盖 / 失去覆盖 |
|---|---:|---:|---:|
| Decision 分数前 10% | 10.43% | 125/200 | — |
| 同预算关联选块 | 10.43% | 157/200 | 36 / 4 |
| Decision 分数前 12% | 12.38% | 133/200 | 8 / 0 |

按 50 个源问题汇总四种长度，关联选块使 22 个源问题的完整覆盖次数增加、3 个减少、25 个不变；四种长度均完整覆盖的源问题由 20 个增至 26 个。

这项结果衡量的是**选中的原文范围是否覆盖全部标注事实**，不是回答准确率，也不证明模型使用了这些事实。不同长度的题来自相同源问题；需要按源问题拆分评测。完整的开发统计见 [coverage.md](coverage.md)。

## 回答质量验证

单 GPU 作业依次对 Qwen3-4B 和 GPT-OSS-20B 跑相同的 200 题，比较全文、关联选块的零更新、ICL Teacher 和训练后 Cartridge，并与既有同题、同模型、同预算的原选块 Cartridge 配对。2026-11-04 04:21 UTC 的开发快照如下，统一使用同一套宽松词面评分：

| 模型 | 已配对题数 | 原选块 Cartridge | 关联选块 Cartridge | 新答对 / 新答错 |
|---|---:|---:|---:|---:|
| Qwen3-4B | 200 | 53.00% | 58.50% | 22 / 11 |
| GPT-OSS-20B | 183 | 52.46% | 60.66% | 21 / 6 |

GPT-OSS 的开发运行和配对仍未完成。按各自已经生成的全部题目计算，关联选块 Teacher 分别为 Qwen 59.50%（200 题）和 GPT-OSS 61.50%（187 题）；当前 Cartridge 尚未超过这些 Teacher。两种结果回答的是不同问题：上表衡量更换选块后的完整方法表现，Teacher 对比衡量同一选块下的表现。

报告还复用已生成的答案，单独比较相同通用输出格式下的零更新和训练后 Cartridge；这能把格式变化与 SD 更新的影响分开。该补充表不改变原先的配置筛选规则，也不会将 Teacher 的答案放进 Student 的提示。

原先的严格目标仍是同时超过全文、零更新、Teacher 和原选块 Cartridge。查看开发结果后，另外增加一条**单独的选块验证规则**：如果关联选块超过配对原选块，且其 Cartridge 不低于同格式零更新，就将该模型推进 800 题源问题不重叠的测试。留出结果会同时报告两条目标；选块验证通过不等于超过 Teacher 三点。

此前有两个留出源问题曾用于定性示例，其四种长度会保留在完整 1,000 题表中，但目标达成判断另排除这 8 题，并报告其余 792 题。之前的其他实验曾使用同一整体数据集，因此这里的“源问题不重叠”特指本次 200 题配置筛选与其余题目之间的划分。

开发集的四路配对读取在诊断阶段保留了选中源缓存；[新的验证路径](../kv_only_cartridge/paired_control.py)会另行生成正式答案，在最终解码前释放全文、选中源缓存与训练状态，并要求其 token 与训练后配对输出一致。

## 使用方式

将仓库安装到 Python 环境后，可从本目录导入实验性选择器：

```python
from experiments.babilong_linked_selection.linked_frozen import LinkedFrozenSelector

selector = LinkedFrozenSelector("/path/to/cached/decision_scores")
selector.bind_case("case-id")
```

选择器读取与现有 `FrozenJSONSelector` 相同的 JSON。只有回答质量实验完成后，才决定是否把它作为默认选块策略。
