# 选块预算对支持事实覆盖的影响

在固定的 200 道 BABILONG 开发题上，使用同一份已缓存的 Decision API 分数，按分数从高到低选择不同数量的块。选择过程不读取标注；选完后才用原始任务的支持事实标注检查覆盖。200 题对应 50 个源问题在四种上下文长度下的样本。

| 目标选块比例 | 实际选中块比例 | 全部标注支持事实被覆盖 | 有标注支持事实未覆盖 |
|---|---:|---:|---:|
| 10% | 10.4% | 125 / 200（62.5%） | 75 / 200 |
| 12% | 12.4% | 133 / 200（66.5%） | 67 / 200 |
| 15% | 15.4% | 140 / 200（70.0%） | 60 / 200 |

实际比例是将所有题的选中块数与总块数分别求和后相除；单题至少选一个块，且选中块数向上取整。这里比较的是**块数**，不是 KV 字节比例。

从 10% 放宽到 12%，这组开发样本中多 8 道题覆盖了全部标注事实，事实覆盖率提高 4 个百分点。额外选中的内容也可能引入干扰，因此这不是回答准确率的提升，也不能单独证明应该改变正式配置。相关性模型和两个视图的推理需要在同题比较后，再到源问题不重叠的留出集验证。

覆盖指选中的原文字符范围包含每条标注支持事实的内容，忽略事实边界的标点。标注未必包含所有必要上下文；覆盖也不证明模型实际使用了事实。这次审计没有新增模型推理或 API 调用。
