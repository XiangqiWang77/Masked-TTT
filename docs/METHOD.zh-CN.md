# Masked TTT via Selective Self-Distillation

## 一句话

**先让同一个模型聚焦相关片段，形成学习信号；再把经过原文检查的信号，写入当前请求的 KV 读取状态，让模型带着全文重新回答。**

这里的学习发生在一次请求内部。基础模型权重保持冻结。回答结束后，临时适配状态随之释放。

## 1. 为什么需要这个方法

长文档问答有两个不同的问题。

第一个是**看得全与看得准之间的取舍**。全文包含必要证据，也包含大量与问题无关的内容。只给模型看少数相关片段，阅读会更聚焦，但选块也可能漏掉必要的条件、后续修订或推理链中的一环。

我们的分工是：**选中片段负责提供聚焦监督，全文负责保留完整的回答条件。** 因此，选择掩码限制“哪里可以被增强”，不会在正常输入范围内删除学生能看到的其他片段。

第二个是**学习目标与答题目标之间的距离**。预测原文的下一个 token，训练的是文档续写。当前问题可能要求比较两个实体、追踪最新状态或综合几条证据。我们把训练位置移到当前问题的回答上：让全文学生学习聚焦教师在这些答案位置的预测分布。

两点合在一起，就是：**保留全文视野，用问题相关的监督改善证据的读取。**

## 2. 输入、输出和可训练状态

输入是文档 $D$、原问题 $Q$，以及原任务的格式要求。输出是学生最后独立生成的答案。

系统使用同一个冻结的语言模型。它承担三种计算：全文编码、选中片段上的教师回答、原文支持检查。没有另外训练一个教师模型。

真正被优化的是当前请求的一小组读取参数：

- **读取份额**：每个选中 chunk、每层、每个 KV head 的注意力偏置。
- **读出内容**：每个选中 chunk、每层、每个 KV head 的低秩 value 映射系数。

这些参数和模型原来的 $W_Q,W_K,W_V,W_O$ 分开存放。优化器不会修改基础模型权重，也不会覆盖原始文档 KV。

## 3. 第一步：按原始 token 位置切块并选块

先用模型自己的 tokenizer 处理完整任务输入，确定文档在输入序列中的准确位置。文档通常按最多 256 个 token 切块，尽量在句子或段落边界结束。

然后调用 OpenAI Decisions API，对每个 chunk 判断：它能否为原问题提供有用证据？问题中的选项也属于原问题的一部分。

判断会考虑直接事实、定义、否定、例外、时间更新和中间推理联系。一个 chunk 不必单独回答整道题；其中有一条必要的线索，也可以有价值。

默认取相关性概率最高的约 10% chunks，并恢复原文顺序。相同分数按原始位置打破平局。API 负责材料相关性，不生成问答监督答案。

记选中集合为 $\mathcal I$，文档位置 $u$ 所属的 chunk 为 $c(u)$，掩码为

$$m_u=\mathbf 1[c(u)\in\mathcal I].$$

未选中的位置仍在学生上下文中，但不获得可训练的读取修正。

## 4. 第二步：建立只读的全文 KV

Transformer 在每层为输入 token 计算 key 和 value。

- **Key** 用于和当前读者的 query 匹配，决定该关注什么位置。
- **Value** 是这些位置被关注后，实际传给后续计算的内容向量。

KV cache 保存已经算过的 key 和 value，使后续 token 可以直接读取之前的内容。

我们先用基础模型正常 prefill 完整工作文档，得到 $K_0,V_0$。这份原始缓存始终只读。之后的训练改变“读取这份缓存时如何分配份额、如何读出 value”，所以每次更新不需要重新编码整篇文档。

如果原始文档超出模型可处理的上下文长度，代码先用同一组 API 分数保留能够放入窗口的原文片段，保持原始顺序，并记录映射。该情况会明确标记为输入缩减；“学生保留全文”对应能够装入窗口的原文，或经过这一明确处理后的完整工作文档。

## 5. 第三步：构建一次生成的 ICL Teacher

教师输入由以下部分组成：

> 原任务要求 + 按原顺序保留的选中片段 + 原问题 + 原输出格式。

教师是同一个冻结模型，使用新建的、只包含这些输入的缓存。它不会从学生的全文缓存里直接抽取一部分 KV 来充当“只看选块”。

教师生成一份回答 $\hat y$。在生成每个 token 时，同时保存对整个词表的概率分布：

$$p_T(\cdot\mid E_{\mathcal I},Q,\hat y_{<i}).$$

教师回答和这些分布随后固定下来。学生更新期间，不重新生成教师答案，也不随学生变化刷新目标。

这里保存分布的意义是：监督既包含教师最偏向的 token，也包含其他候选 token 的相对概率。这部分区别于唯一硬标签的信息，通常称为 **dark knowledge**。代码使用完整词表分布，而不是只把教师最终答案当成一个 one-hot 标签。

## 6. 第四步：检查这份教师信号是否值得学习

教师聚焦了相关片段，但它也可能漏掉条件。因此，当前版本在更新之前执行原文支持检查。

实际流程是：

1. 在选中原文视角和全文视角检查候选回答，收集源文本证据。
2. 在不提供候选回答的情况下，再从原文提取与问题有关的证据。
3. 把提取的引文与原文核对，保留能够定位的原文内容。
4. 将原任务、问题、已核对引文和候选回答交给最终检查，判断该候选是否得到支持。

检查器不会改写教师答案。检查器的解释、引文和结论也不会被拼入正式回答的提示中。

当前固定策略是：

| 最终检查状态 | 更新预算 |
|---|---:|
| 原文支持该候选 | 最多 16 步 |
| 原文与该候选矛盾 | 0 步 |
| 尚未确认支持 | 0 步 |
| 无可用答案或检查无法解析 | 0 步 |

因此，**Selective SD 在这里选择的是“是否采用这份教师信号更新内部状态”**。它不是逐 token 的教师加权，也不是把教师分布与原模型分布按某个 $\alpha$ 混合。

0 步时，读取修正保持为零，学生直接在原始全文工作缓存上回答。

## 7. 第五步：具体增强 KV 的哪一部分

对一个注意力层和一个 KV head，设原始文档位置 $u$ 的缓存为 $k_{u,0},v_{u,0}$。

### 7.1 调整选中片段被读取的份额

原来的注意力分数是

$$z_{t,u}^{\mathrm{base}}=\frac{q_t^\top k_{u,0}}{\sqrt{d_h}}.$$

我们在选中位置上加一个按 chunk 共享的偏置：

$$z_{t,u}=\frac{q_t^\top k_{u,0}}{\sqrt{d_h}}+m_u g_{c(u)}.$$

偏置为正时，该 chunk 在相同 query 下获得更多读取份额；为负时则更少。它保持块内部由 query–key 匹配得到的相对分配。

$q_t$ 仍由冻结的 $W_Q$ 计算。GQA 中属于同一 KV head 的 query heads 共享该偏置。实现将偏置编码到 RoPE 之后临时增加的 Q/K 维度，保留原来的 attention scale；不会改写原始 K。

### 7.2 调整选中位置读出的内容

我们先从选中位置的原始 V 计算未减均值的二阶矩，并取其主要方向，形成固定低维基 $U$。每个选中 chunk 有自己的可训练系数 $B_c$。

$$\Delta v_u=(v_{u,0}U)B_{c(u)},\qquad U\in\mathbb R^{d_h\times r},\quad B_c\in\mathbb R^{r\times d_h}.$$

默认 $r=8$。$U$ 在一次请求内固定，只训练 $B_c$。每个位置的修正还受到范数限制：

$$\lVert\Delta v_u\rVert\leq0.15\lVert v_{u,0}\rVert.$$

实际读出的值为

$$\widetilde v_u=v_{u,0}+m_u\Delta v_u.$$

原始 V 保留；读取分支临时构造 $\widetilde V$。未选中位置、开头的 sink 位置，以及问题和生成 token 不附加这类文档修正。

### 7.3 两种修正一起生效

$$o_t=\sum_u\operatorname{softmax}(z_t)_u\widetilde v_u.$$

“读多少”和“读到什么”在同一次读出中共同影响答案，所以两者在同一个损失下联合更新。

初始偏置和系数都为零，模型走原来的 native 读取路径。默认 Qwen3-4B 使用全部 36 层，即层号 0–35；每层的 8 个 KV heads 各自有状态，同组 query heads 共享读取偏置。

## 8. 第六步：用标准 KL 做自蒸馏

学生在全文条件下，按照教师的答案前缀计算下一 token 分布：

$$p_{\theta,\phi}(\cdot\mid D,Q,\hat y_{<i}),\qquad\phi=(g,B).$$

目标是

$$\mathcal L(\phi)=\frac1M\sum_{i=1}^{M}
\mathrm{KL}\!\left[p_T(\cdot\mid E_{\mathcal I},Q,\hat y_{<i})
\,\Vert\,p_{\theta,\phi}(\cdot\mid D,Q,\hat y_{<i})\right].$$

这是**标准前向 KL**。没有 centered-SD 目标，也没有原文 NTP 项。

预测 $\hat y_i$ 时，学生只输入之前的 $\hat y_{<i}$。当前目标 token 不提前放进缓存。梯度可以穿过冻结模型的计算，但最终只更新当前请求的 $g$ 和 $B$。

当前更新器的执行顺序是：

1. 对两组读取状态同时求 KL 梯度。
2. 用 Adam 的矩估计形成两个更新方向。
3. 在这两个方向上估计输出分布的局部变化，考虑两种修正之间的耦合。
4. 提议联合步长，并通过回溯检查实际 KL 是否下降、输出变化是否在限制内。
5. 接受通过检查的更新；否则恢复该步之前的状态。

它还保留了已有的问题条件保护：对于触发条件的、已经明确表达在共同答案前缀中的问题限定词，限制更新造成的冲突。该检查只约束特定前缀位置，不把原模型的整份答案改成蒸馏目标。

这里的曲率计算是优化器选择步长的方式；教师分布和标准 KL 目标始终固定。代码不会把教师或 ICL 本身定义为“一阶梯度”。

## 9. 第七步：重新回答

训练完成后固定适配状态。清除训练和检查产生的问题、答案及解释后缀。

接下来，从原始文档缓存出发，使用最终读取状态重新计算原问题和回答起始，再从头生成答案。教师答案不会作为额外文本提示交给正式生成。

因此，最终学生并非直接返回教师文本。它使用经过适配的读取过程，在完整工作文档上自行生成。请求结束后，适配参数与优化器状态被释放。

## 10. 用一个例子理解

假设文档包含：X 初始预算 300 万、X 最终批准预算 320 万、Y 最终批准预算 250 万，以及大量其他内容。问题问：X 的最终批准预算比 Y 多多少？

选块寻找与 X、Y、最终批准有关的原文。教师聚焦这些材料形成回答及其 token 分布。原文支持检查确认它使用的是最终批准金额，并核对两个实体。

通过检查后，学生在全文条件下学习这份回答分布。训练让选中信息的读取份额与 value 读出更适合当前问题。正式回答时，学生带着学到的状态重新读题和推理。

如果教师混用了初始预算与最终预算，源文本检查有机会阻止这份信号更新；学生仍然保有全文工作缓存。

## 11. 三个核心设计

| 设计 | 解决的问题 | 具体作用 |
|---|---|---|
| Chunk guidance | 学习材料分散，相关证据容易被大量无关内容稀释 | 用问题选择监督来源，并把可写状态限制在选中位置 |
| KV-based adaptation | 需要在当前请求内改变证据读取方式 | 在基础权重和原始文档缓存不变的条件下，联合调整读取份额与读出内容 |
| Selective self-distillation | 文档续写目标与当前答题目标有距离，教师也可能有偏差 | 使用经过原文支持检查的答案分布训练全文学生 |

最值得带走的理解是：**文本中的证据、对证据的读取方式、以及最终生成的答案，是三个可以分别处理的对象。选块选择监督材料，KV 适配改变内部读取，自蒸馏把更新方向接到当前问题上。**

## 12. 时间是怎样记录的

在线 TTFT 从方法收到请求开始，包含切块与 API 选择、全文 prefill、教师生成、原文检查、适配以及正式首 token。模型加载时间和集群排队时间单独看，不计入这个值。API 缓存命中会明确记录。

当前主流程按这些阶段顺序执行。长输入在反向传播时采用逐层重算来控制显存。KV 状态允许复用原始文档编码，选块限制了可写范围；实际总时间还取决于教师、检查和优化的成本。
