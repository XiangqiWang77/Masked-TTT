# Query Cartridges：通过 Masked TTT 学习如何读取长文档

全文可能包含最完整的证据，但大量无关内容会增加查找难度；只看选中的片段更聚焦，也可能漏掉必要条件。我们用选中片段提供学习信号，让学生在全文下学习读取，并额外评估能否只保留一个更小的 Query Cartridge 回答。

## 1. 选块并建立 Teacher

Decision API 根据问题为原文块打分，默认选取得分最高的 10%，并按原文顺序排列。已保存的 JSON 可以跨模型复用。冻结的模型只看这些片段和原问题，形成聚焦的 ICL Teacher；另一路对完整工作文档做 prefill，保存原始 KV Cache。

当原文超过模型的上下文窗口时，系统会构造选中内容优先的工作文档并记录映射。这里的“全文”指模型实际能够处理的工作文档。

## 2. 构造原文支持的小练习

Teacher 从选中片段提出最多两个事实性问题，给出短答案和支持该答案的原文引用。系统要求引用逐字来自选中块、答案出现在引用内，再让冻结模型只看这条引用独立回答小题，筛掉前后不一致的练习。

这些检查不使用评测标准答案，也不保证所有保留下来的问答都蕴含于原文。小练习是训练信号，不直接给出原问题的答案。

## 3. 在全文 KV 的读取上学习

学生的基础模型权重和原始 KV 均冻结；只有选中位置的两类请求内状态参与更新：一类调整不同选中块获得的注意力，另一类通过按块低秩残差调整从 Value 读出的内容。未选中位置保持原有读取方式。

训练采用 on-policy self-distillation。对原问题和通过检查的小问题，学生先生成短前缀，Teacher 在相同前缀下预测下一词；两者的完整概率分布通过前向 KL 比较，梯度同时更新两类读取状态。每一步刷新学生前缀，所有小问题共享同一份状态。

Teacher 的完整分布带来不止一个最高概率词的信息，例如多个候选答案的相对偏好；但分布也可能有偏，最终收益要看实际回答。

## 4. 两种回答方式

**全文 KV＋Query Cartridge** 使用全文工作缓存和训练后的状态重新处理原问题。冻结模型再根据全文，分别以两个候选顺序比较原始回答和适配回答；只有判断满足预设条件才采用适配回答，否则保留原始回答。

**独立 Query Cartridge** 把独立 prefill 得到的选中块 KV 与学到的读取状态组合，重新处理原问题，不读取全文 KV。这个回答单独评测，不借用全文 Judge 的结果。

前者继续保留全文视野；后者有机会减少回答阶段需要保存的文档状态。适配阶段仍需要全文 KV，因此应将回答时缓存大小与完整运行的峰值显存分开报告。

## 5. 实验怎样衡量

对同一批问题统一比较 Vanilla、qTTT、ICL Teacher、全文 KV＋Cartridge 和独立 Cartridge 的正确率，以及相对 Teacher 和 Vanilla 的新增答对与新增答错。内存表分别报告全文 KV、读取状态、独立 Cartridge 和带模型的实际运行峰值。

旧版本的实验结果不自动代表当前 OPD＋小练习版本；每个新版本都需要使用它自己的成对结果。
