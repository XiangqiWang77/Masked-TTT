# BF16 Value 写回诊断

## 为什么检查

现有实现先在 FP32 中计算选中位置的 Value 修正，再把修正写回 BF16 缓存。如果修正远小于原始 Value 的舍入间隔，非零的训练参数和非零梯度并不一定意味着物化后的缓存发生了同等幅度的变化。注意力偏置保存在独立扩展维，不受这里的逐元素 Value 加法影响。

## 受控数值实验

以下是随机生成 BF16 Value、随机正交 rank-8 基底、随机符号系数的结果；不使用模型、真实题目或标签。`B` 是每个合成系数的绝对值，而不是准确率或模型训练步数。

| 合成 B 幅度 | head dim | 写回后变化的 Value 分量 | 误差平方 / 目标修正平方 |
|---:|---:|---:|---:|
| 0.0001 | 64 | 6.7% | 0.892 |
| 0.0002 | 64 | 13.1% | 0.789 |
| 0.0010 | 64 | 51.0% | 0.260 |
| 0.0050 | 64 | 87.7% | 0.014 |
| 0.0001 | 128 | 6.6% | 0.891 |
| 0.0002 | 128 | 13.0% | 0.789 |
| 0.0010 | 128 | 50.6% | 0.262 |
| 0.0050 | 128 | 87.5% | 0.014 |

数值是三个随机种子的平均值。误差定义为 `||写回后变化 − FP32 目标修正||² / ||FP32 目标修正||²`；“变化分量”只表示结果不同，不衡量回答是否变好。

进一步使用随机初始化的两层 Qwen3 和 GPT-OSS 小模型，在 BF16 下完整运行两步全文 Student SD，检查独立选中缓存。两个模型使用 `value_learning_rate=0.0001` 时约 10%–11% 的 Value 分量改变；设为 `0.001` 时约 69%–70% 改变。小模型 head dim 为 8、rank 为 2，因此这只是端到端代码路径的数值验证，不是对完整模型最佳学习率或准确率的结论。

## 真实模型怎样核验

只读探针在训练结束、Cartridge 物化之前，对独立选中 KV 的固定样本计算目标修正、BF16 实际变化和上述误差；不修改模型、缓存、训练目标或答案。探针在两个架构的小模型上通过了与真实物化结果一致、与未启用探针输出一致的测试。它已接入待执行或重新启动的基底配对任务；已经开始执行并加载旧代码的进程不会受到影响。

真实模型若也显示大比例写回损失，可在相同 Teacher、全文 Student、选块和问题格式下，以独立开发集配对比较 Value 学习率；再用未参与调参的题验证准确率、新答对与新答错。数值变化更大并不自动代表质量更好。
