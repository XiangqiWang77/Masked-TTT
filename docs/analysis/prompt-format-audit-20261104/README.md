# 复现 OLMo 涨点：回答格式和卡带更新的配对检查

这些结果来自已完成的 BABILONG 配对日志，**没有重新训练、生成或调用 API**。每行的两个零更新答案使用相同模型、独立选中 KV 和生成预算：一个沿用原问题，另一个增加 Teacher 使用的通用回答格式要求。训练后答案与原问题零更新答案也使用相同缓存、问题格式和生成预算。所有答案用同一套宽松词面判分；参考答案只用于生成后的评分。

| 模型与数据 | 原问题零更新 | 加通用格式要求的零更新 | 训练后，原问题格式 | Teacher |
|---|---:|---:|---:|---:|
| Qwen3-4B，原选块 1,000 题 | 56.00% | 56.60% | 56.70% | 56.60% |
| GPT-OSS-20B，原选块 1,000 题 | 55.10% | 57.10% | 55.40% | 57.10% |
| Qwen3-4B，关联选块开发集 200 题 | 57.50% | 59.50% | 58.50% | 59.50% |
| GPT-OSS-20B，关联选块开发集 200 题 | 61.00% | 62.00% | 61.00% | 62.00% |

例如，GPT-OSS 的原选块 1,000 题中，只改通用格式要求产生 47 个新对、27 个新错，净增 **2.00 个百分点**；在原问题格式下做训练产生 8 个新对、5 个新错，净增 **0.30 个百分点**。这是两个分别对照零更新的变化，不能相加作为同一次推理的总收益。关联选块的 200 题由 50 个来源问题各扩为四种长度，也不是 200 个独立来源问题。

按题型拆分，GPT-OSS 的 100 道 QA10 中，原格式零更新为 38%，加通用格式要求后为 50%，贡献了上述变化中的大部分。这是对同一缓存两种输出的直接比较，也说明需要检查回答内容本身；格式提示不仅可能改变句子长度，也可能改变答案选择。聚合文件列出全部题型，不能据此假设其他题型一定受益。

通用格式要求使原选块 1,000 题中 Qwen 的 131 题、GPT-OSS 的 81 题生成首 token 改变。在这些题里，训练后的原格式答案相对零更新分别有 9 新对／2 新错和 5 新对／2 新错；其余题分别有 6／6 和 3／3。这个事后分组说明输出方式是值得核查的因素，**不证明训练收益是由格式引起**，也不证明首 token 改变只代表格式改变。

选中 Teacher 和相同格式零更新的 token 序列分别在 7 / 1,000 和 1 / 1,000 题上不同；二者的生成长度上限可能不同，所以不要求所有序列逐位一致。同格式对照不能单独解释全文 Student 的训练行为。当前实验保留 OLMo 的训练与物化方法，同时记录原问题和通用格式两种配对输出，便于把提示带来的变化与 SD 的贡献分开评估。
