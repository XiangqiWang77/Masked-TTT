# Qwen 计数题：读取与自练习信号

这份分析使用已完成的 Qwen BABILONG 1,000 题中的 **100 道计数题**，即 25 个来源问题各有四种长度。参考答案和支持事实只在生成后用于统计；答案用统一的 `answer_focused_lexical_v2` 宽松词面规则重新评分。所有输出都能解析为数字。

| 方法 | 答对 | 报得偏多 | 报得偏少 |
|---|---:|---:|---:|
| 全文模型 | 41 | 52 | 7 |
| ICL Teacher | 42 | 50 | 8 |
| 选中缓存零更新，原问题格式 | 28 | 65 | 7 |
| 独立 Cartridge，原问题格式 | 32 | 62 | 6 |
| 同训练状态，Teacher 通用格式 | **43** | 49 | 8 |

这批题的参考答案中 68 题为 0，32 题为 1。Teacher 答错的 58 题中，49 题已覆盖全部标注支持事实。若再检查源故事中提及问题人物、但不属于标注支持事实的句子，31 题全部覆盖、21 题没有此类额外句子、6 题至少漏掉一条。人物句子是否必要并未在此判断；文档中其他上下文和干扰也可能影响回答。数据提示应优先检查物品状态的更新与计数，而不是只按人物名继续补选块。

自练习日志提供了另一个可操作线索：100 题中仅 5 题得到至少一个经过原文核验的小题；77 题的输出无法解析为 JSON。这 77 次输出长度中位数为 **2 个 token**，没有一次达到 192-token 上限，因此不能把主要原因归为生成长度截断。原日志没有保存这 77 次生成的原文，不能据此断言模型具体输出了什么。

后续探针复用同一个已选 Teacher 缓存，比较原自练习提示与“原问题仅用于确定学习材料，请勿直接回答”的措辞；两边仍执行原有逐字证据检查和独立问答核验。它已挂到 Qwen 作业 `32002505` 的可选预检，最多比较 5 个来源问题的 8K、32K 版本，每次分配最多运行 6 分钟，不额外提交 GPU 作业。只有作业在启用后到达该预检时才会运行。探针不读取评测答案，不更新模型或 KV，也不改变主实验；[真实 Qwen tokenizer 检查](tokenizer_check.json)验证了 10 个问题的全文和选中缓存前缀一致。核验小题数量是否增加以及最终准确率能否提高，仍由后续实测判断。

通用格式的卡带输出为释放前配对诊断；原问题格式卡带为正式输出。Teacher 与原格式卡带的提示不同，因此表中的差异不能全部归因于 TTT。事后对齐支持事实也不能证明模型是否使用了它们。[聚合数据](summary.json) · [复核脚本](../../../experiments/babilong_linked_selection/qa7_count_error_audit.py) · [探针代码](../../../experiments/self_study_prompt/probe.py) · [测试](../../../tests/test_qa7_count_error_audit.py)。数据文件不含题目、答案或逐题 ID，没有新模型或 API 调用。

## 自练习措辞的后续配对

原有小题提示包含原问题，随后又要求输出 JSON 小题；待测措辞把原问题标成“只用于识别需要练习的事实”，不要求模型先回答它。[study_context.py](../../../experiments/self_study_prompt/study_context.py) 将这一改动限制在小题生成，保留原有的原文逐字引用与独立问答核验；真正的原问题、Teacher、全文 SD 目标以及最终卡带生成都沿用原流程。

[run_study_prompt_pair](../../../experiments/prompt_alignment/same_gpu_pair.py) 可在同一设备上顺序运行原措辞与候选措辞，要求选块、Teacher token、零更新输出一致；练习本身允许不同。两套缓存分别 prefill 并在最终解码前释放，返回的答案仅供生成后统一评分。测试覆盖了主问题后缀保持一致和异常时恢复临时钩子。

这些工具默认不会修改原方法，也不会插入正在运行的主实验。小模型测试只证明流程可执行；真实模型能否产生更多经核验的练习、以及答案质量是否改善，都要以 GPU 探针和后续配对评测为准。

## 条件触发的答题实验

已冻结一项单 GPU、200 题的真实模型配对实验。它只会在既有的 10 题无标签探针全部完成、且候选措辞产生更多经原文核验的练习时提交；此时依然不能认为答题质量已提升。两组独立重建全文和选中缓存，比较原 SD 与候选 SD 的最终卡带答案，并在同一请求内对照全文、选中缓存零更新和 ICL Teacher。

200 题均有效、候选答案同时超过这四个对照时，才自动提交来源问题互不重叠的 800 题留出集。使用缓存的 Decision JSON 和统一的宽松词面评分；参考答案只在生成之后评分。每个作业请求一张 GPU，遵守项目最多 12 张的共享限制。汇总按一小时一次执行。两题留出来源曾在以往分析中查看，其他选块配置的整体汇总也曾查看，因此最终报告不称其为完全盲测。

冻结环境的 CPU 测试已通过；CUDA 测试和真实模型预检在分配到 GPU 后执行。条件触发不代表该 200 题作业已经提交，也不保证候选会通过质量门槛。[冻结和提交逻辑](../../../experiments/self_study_prompt/study_job.py) · [配对评分](../../../experiments/self_study_prompt/study_report.py) · [门槛](../../../experiments/self_study_prompt/study_gate.py)。
