# 为什么需要检查卡带的实际更新效果？

这份审计读取 OLMo、Qwen3-4B 和 GPT-OSS-20B 已完成的 BABILONG 逐题日志，每个模型各 1,000 题。三个模型都使用缓存的 Decision 选块、选中 ICL Teacher、全文 Student 的 on-policy KL 更新，以及独立选中缓存解码。每 1,000 题由 250 个来源问题在四种上下文长度下构成。无需模型调用或在线 API；参考答案只用于已生成结果的评分。

| 模型 | 至少一个已验证自练习 | Teacher 准确率 | Cartridge 准确率 | 相对 Teacher | 同缓存零更新后生成 token 有变化 |
|---|---:|---:|---:|---:|---:|
| OLMo-3-7B | 170 / 1,000 | 41.20% | 44.60% | +3.40 点 | 原始运行未记录此配对 |
| Qwen3-4B | 174 / 1,000 | 56.60% | 56.70% | +0.10 点 | 57 / 1,000 |
| GPT-OSS-20B | 421 / 1,000 | 57.10% | 55.40% | −1.70 点 | 25 / 1,000 |

最后一列比较相同选中 KV、相同原问题、相同生成预算下，训练前后的整个生成 token 序列；变化不等于答对。Qwen 的配对结果为新答对 15、新答错 8；GPT 为新答对 8、新答错 5。训练后的 token 很少改变，是检查训练信号是否传到物化卡带读出的直接动机。

Teacher 使用额外的通用输出格式要求，而上表 Cartridge 使用原问题格式。对 Qwen 和 GPT 分别把这个要求加到**同一选中缓存**的零更新与训练后答案中，准确率为 56.60% → 56.80% 和 57.10% → 57.50%。OLMo 另一轮配对复跑是 44.30% → 44.50%。因此，原始 OLMo 的 +3.40 点是完整方法与当时 Teacher 设置的比较；不能将全部差值归因于 SD 更新。

在 OLMo 原始运行的 830 道无已验证自练习的题中，Cartridge 为 42.65%，Teacher 为 39.04%，净多答对 30 题；其余 170 题净多答对 4 题。这是事后分组，不能证明生成练习是否造成增益。GPT 的 421 道有已验证练习的题中，原问题格式下仅有 9 道的训练前后 token 序列改变；在这些题的同格式零更新对照中也有正负变化。提高学习率、增加步数和检查物化精度分别针对“更新幅度”和“写入效果”做配对验证，不能仅凭梯度大小断言哪种配置更准确。

按题型看，Qwen 的 100 道 QA3 题首步 KL 中位数为 $2.24\times10^{-8}$，同缓存训练前后的生成 token 没有变化。历史 19 题严格配对检查中，将学生前缀从 8 个 token 延长至 11 个后梯度明显改变，但最终独立卡带答案仍没有变化。于是新的步数实验同时检验更长前缀与多步更新，而不是把梯度变大直接当成准确率提升。

首次更新的 KL 和梯度范数中位数、各题型及按练习数量的分组保存在 [summary.json](summary.json)。它们由不同词表、模型和提示产生，不能当作跨模型统一能力尺度。分析使用 [audit_practice_signal.py](../../../experiments/value_lr_physical/audit_practice_signal.py)；汇总不包含原文、答案或单题身份。历史配对运行解码时仍保留选中源缓存和训练状态，独立卡带的物理释放由新的冻结运行另行验证。
