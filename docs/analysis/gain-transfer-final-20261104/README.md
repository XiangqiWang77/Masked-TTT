# 全文训练的更新在独立卡带上有多大影响？

机制探针已完成：Qwen3-4B 和 GPT-OSS-20B 各 40 题，来自 10 个来源问题，每个问题使用四种上下文长度。训练仍是选中 Teacher、全文 Student 的原 SD；记录的是同一个原问题、首个答案 token 的完整词表分布。没有使用参考答案或在线 API。

| 模型 | 全文更新前后 KL 中位数 | 独立选中缓存更新前后 KL 中位数 | 逐题选中变化 / 全文变化的中位数 | 首步注意力更新中的共同分量 |
|---|---:|---:|---:|---:|
| Qwen3-4B | 0.001987 | 0.0000111 | 0.0117（38 题） | 26.9% |
| GPT-OSS-20B | 0.0000103 | 0.0000108 | 0.8588（35 题） | 18.7% |

前两列分别测量各自阅读视图在更新前后的分布变化。比例先逐题计算，再取中位数；只有全文更新前后 KL 大于 $10^{-8}$ 的题进入该比例。Qwen 在这批题上呈现出一个具体问题：全文读取已经改变，独立选中缓存的首 token 分布变化通常小得多。GPT 的变化模式不同，不应直接套用 Qwen 的结论。

共同分量是同层同头的所有选中 chunk 一起变化的部分，以其平方范数占更新平方范数的比例计算。Qwen 和 GPT 的全部 87、104 个非零更新中，没有任何一步超过 90%。因此，单凭“选中块加了同一个偏置会被 softmax 抵消”不能解释整体现象；Value 修正及两种缓存表示的差异仍需要单独检查。

这些是首 token 的分布诊断，**不是正确知识转移率，也不是准确率**；它不能证明模型是否恢复了全文中遗漏的事实。实际回答收益继续由物理释放后的卡带评测衡量。完整聚合数据见 [summary.json](summary.json)，复核脚本见 [freeze_final_gain_transfer.py](../../../experiments/value_lr_physical/freeze_final_gain_transfer.py)，两者不包含题目、逐题 ID 或生成答案。
