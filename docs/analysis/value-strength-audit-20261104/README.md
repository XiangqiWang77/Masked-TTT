# Value 更新强度：Qwen 与 GPT-OSS 的配对检查

这份分析复用每模型已完成的 BABILONG **200 题开发集**，其中 50 个来源问题各有四种长度。三种设置使用原 Decision 分数选出的约 10% 块和原 OLMo 式 on-policy SD，只改变 Value 学习率；共同的注意力增益学习率为 0.01。

脚本逐题核验三种设置的选块、Teacher token、已核验练习、第一次学生前缀、零更新答案及 GPU allocation 一致。模型权重与原文 KV 冻结，训练不使用评测答案。表中的新对和新错都相对于**相同选中缓存、相同原问题格式的零更新**；得分由同一个宽松词面规则在生成后计算。

| 模型 | Value 学习率 | Teacher | 零更新 | 训练后 | 新对 / 新错 | 输出 token 序列改变 | Value 相对变化中位数 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Qwen3-4B | 0.0001 | 52.50% | 52.00% | 52.50% | 4 / 3 | 12 / 200 | 0.118% |
| Qwen3-4B | 0.0003 | 52.50% | 52.00% | 52.50% | 6 / 5 | 18 / 200 | 0.382% |
| Qwen3-4B | 0.0010 | 52.50% | 52.00% | 51.50% | 7 / 8 | 27 / 200 | 1.125% |
| GPT-OSS-20B | 0.0001 | 53.50% | 52.50% | 52.50% | 1 / 1 | 4 / 200 | 0.088% |
| GPT-OSS-20B | 0.0003 | 53.50% | 52.50% | 53.50% | 2 / 0 | 6 / 200 | 0.333% |
| GPT-OSS-20B | 0.0010 | 53.50% | 52.50% | **54.00%** | 4 / 1 | 14 / 200 | 1.046% |

GPT-OSS 在这三个设置中随更新变强出现了更多答案变化，0.001 相对零更新净增 **1.50 点**；Qwen 的 0.001 在同批题上净减 0.50 点。因此当前将模型分别校准：GPT-OSS 的 0.001 正在 800 题留出集验证；Qwen 继续检查选块、训练前缀与问题格式。现有结果不意味着再增大学习率一定有益。

Value 相对变化是在独立选中缓存上按缓存数据类型模拟写入，最多均匀采样 256 个选中 token，汇总适配层与头后逐题计算范数比例，再取中位数。它描述写入强度，不等于事实或准确率提升。Teacher 额外带通用回答格式要求，训练前后卡带使用相同的原问题格式；这份开发集上的旧配对解码不作为严格的独立解码显存测量。

[聚合数据](summary.json)包含各题型和长度拆分，不含题目、答案或逐题 ID；[复核脚本](../../../experiments/value_lr_physical/audit_value_strength.py)和[测试](../../../tests/test_value_strength_audit.py)不运行模型，也不调用 API。
