# 相同训练状态下的卡带写入精度对照

这项已完成的真实模型实验，在同一份训练状态上比较 BF16 与 FP32 Value 卡带。每个模型各有 **56 题**，由 14 个来源问题各扩展成 8K、16K、32K、64K 四种长度；其中 20 题来自 QA3。各组共享选块、Teacher 和训练状态，最终独立卡带答题。指标统一为 `answer_focused_lexical_v2` 宽松词面评分。

| 模型 | Teacher | BF16 零更新 | BF16 训练后 | FP32 零更新 | FP32 训练后 |
|---|---:|---:|---:|---:|---:|
| Qwen3-4B | 53.57% | 50.00% | **53.57%** | 50.00% | **53.57%** |
| GPT-OSS-20B | 41.07% | 39.29% | **39.29%** | 39.29% | 37.50% |

在 Qwen 这 56 题中，两种精度的训练后回答分数相同；生成 token 序列在 2 题不同，首个生成 token 均相同。在 GPT-OSS 中，训练后的两种精度有 1 题生成序列不同，这题 BF16 答对而 FP32 答错。Qwen 在该小样本上相对同缓存 BF16 零更新新答对 2 题、没有新答错；这 3.57 点是**相对零更新**，不是相对 Teacher。

卡带本体大小相对全文文档 KV 的逐题中位比例为：Qwen BF16 **14.39%**、FP32 **21.58%**；GPT-OSS BF16 **21.57%**、FP32 **30.28%**。这是卡带字节数，不包含模型权重和训练峰值。配对诊断运行 FP32 时还临时保留 BF16 卡带，因此表中比例不是配对实验的显存峰值。

两个实现使用不同注意力后端：BF16 走常规后端，FP32 Value 使用 eager attention，所以差异同时包含精度和后端影响。Teacher 带通用输出要求，学生使用原问题格式。这是开发样本，且四种长度共享来源问题；不能把它当成 1,000 题结果。它支持**暂时保留 BF16**，并继续测试原方法下的选块与更新强度。

本报告重新读取生成结果并独立运行同一评分脚本，逐题核对了已保存的配对记录；参考答案只在生成之后使用，没有新模型或 API 调用。[聚合数据](summary.json)不含题目、答案或逐题 ID；[复核脚本](../../../experiments/precision_cartridge/freeze_completed_pilot.py)和[原实验实现](../../../experiments/precision_cartridge/benchmark_report.py)可复现统计。
