# 在已有 GPU 作业中验证请求级卡带

目标是在 Qwen3-4B 和 GPT-OSS-20B 的真实模型上，检查新的 `compact_standalone=True` 入口是否与已经验证的冻结版本输出一致。验证复用已提交作业加载的模型，不提交新 GPU 作业，不调用 Decision API。

作业已有一个默认关闭的可选预检入口。[启用脚本](../../../experiments/kv_only_cartridge/enable_in_job_probe.py)把独立的验证文件和候选 `pipeline.py` 快照放到请求私有目录，不覆盖作业的训练运行时。两个作业共享结果与锁：同一模型一旦验证通过，其余作业不会重复跑；如果预检失败，最多尝试两次，并保留失败信息。预检只会在当前分配还有足够时间时执行。

[预检实现](../../../experiments/kv_only_cartridge/in_job_probe.py)使用一条合成请求，分别运行冻结版的既有 KV-only 路径和候选请求级路径。它检查：

- 两步自蒸馏的 Student 前缀、Teacher token、KL 和两组梯度一致。
- 物化后的回答 token 与各生成位置的 logits 一致。
- 解码前全文 KV 已释放，选中源缓存和训练参数没有额外占用，物化卡带不保留重复适配参数。
- 模型配置、随机状态和验证用钩子在结束后恢复，原模型权重及原始 KV 保持不变。
- 同一个物化卡带使用通用回答格式时，释放源缓存前后的生成 token 相同；该格式不包含 Teacher 的答案。

GPT-OSS 的聊天模板带有当前日期；配对的两次调用固定同一个日期，避免跨午夜时把提示变化误判为卡带差异。

该检查只验证部署与数值一致性；BABILONG 准确率仍由原作业单独评估。小模型测试已在当前代码和已提交作业的冻结运行时上通过。Qwen 与 GPT-OSS 的真实 GPU 检查结果待对应模型作业启动后记录。

[结果汇总脚本](../../../experiments/kv_only_cartridge/in_job_report.py)接入现有的每小时报告，只读取预检结果文件，不额外查询调度器。真实 GPU 通过、失败、尚未运行和记录不完整会分别标明。
