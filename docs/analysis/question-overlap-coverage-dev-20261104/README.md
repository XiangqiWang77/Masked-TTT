# 同预算下的 Qwen 问题词补选开发实验

前一项分析发现，全文答对而 Teacher 答错的部分题目漏选了标注支持事实。这里在原有 Decision API 缓存分数之上尝试问题词补选，**每题选中块数保持不变**：200 题共选 2,449 / 23,474 块，约 10.43%。所有选择函数只接收文档、问题和已有分数；支持事实与参考答案仅在选块之后用于统计。

| 选块策略 | 改变选块的题数 | 支持事实完整覆盖 | 新覆盖 / 失去覆盖 | 全文对、Teacher 错的题中新增覆盖 |
|---|---:|---:|---:|---:|
| 原实体关联选块 | 0 | 157 / 200 | — | — |
| 对所有问题混合问题词 | 121 | 165 / 200 | 13 / 5 | 6 |
| 对所有问题按问题词补选 | 146 | 155 / 200 | 13 / 15 | 7 |
| 仅对简单专名定位问题混合问题词 | 7 | **163 / 200** | **6 / 0** | **5** |

最后一行只在问题文本符合 `Where is + 单个首字母大写词？` 时启用补选，其余问题使用原选块。这个匹配是轻量文本规则，并不保证识别出的人名一定是人物。候选在查看前两种策略的开发集结果后设计，属于开发集调参；它没有使用题型 ID 或标准答案做推理时路由。

此表衡量的是事实跨度覆盖，不是新策略的回答准确率。200 题来自 50 个来源问题各四种长度；即使新增支持事实被保留，模型仍需正确读出并回答。新旧选块的 200 题答题比较已经完成：候选卡带提高 1.50 点，但仍低于同轮 Teacher，因未达到预定条件而没有扩展到 800 题。[完整配对结果](../qwen-proper-where-dev-20261104/README.md)。
