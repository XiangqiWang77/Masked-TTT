# 检查蒸馏前缀长度

这份分析使用事先固定的 Qwen3-4B 693 题和 GPT-OSS-20B 563 题历史快照。逐题读取训练日志中原问题的第一条学生前缀，并用模型和分词器配置中的 EOS token 判断前缀是否在结束前达到 8-token 上限。没有重新运行模型或 Decision API。

| 模型 | 快照题数 | 前缀到达 8 token | 到达 8 token 时没有 EOS | 对应卡带准确率 |
|---|---:|---:|---:|---:|
| Qwen3-4B | 693 | 207 | 159 | 56.42% |
| GPT-OSS-20B | 563 | 163 | 108 | 55.77% |

在前缀到达 8 token 的组中，零更新选中缓存准确率分别为 37.20% 和 32.52%；前缀更短的组分别为 63.99% 和 64.50%。两组题目的难度可能不同；到达上限也不代表最终答案一定还没有出现。因此这只是检验更长前缀的动机，不能作为“延长前缀会提升准确率”的结论。

新的对照保持原来的 10% 选块、Teacher、全文 Student、SD 目标与独立卡带，只把学生前缀上限由 8 改为 32。在相同参数状态下，如果前缀在 8 token 前产生 EOS，提高上限不会延长那次生成；后续优化仍可能改变生成路径。先对固定的 200 题进行配对比较，再将有效配置用于来源问题不重叠的留出题。
