# 检查蒸馏前缀长度

这份分析使用事先固定的 Qwen3-4B 693 题和 GPT-OSS-20B 563 题历史快照。逐题读取训练日志中原问题的第一条学生前缀，并用模型和分词器配置中的 EOS token 判断前缀是否在结束前达到 8-token 上限。没有重新运行模型或 Decision API。

| 模型 | 快照题数 | 前缀到达 8 token | 到达 8 token 时没有 EOS | 对应卡带准确率 |
|---|---:|---:|---:|---:|
| Qwen3-4B | 693 | 207 | 159 | 56.42% |
| GPT-OSS-20B | 563 | 163 | 108 | 55.77% |

在前缀到达 8 token 的组中，零更新选中缓存准确率分别为 37.20% 和 32.52%；前缀更短的组分别为 63.99% 和 64.50%。两组题目的难度可能不同；到达上限也不代表最终答案一定还没有出现。因此这只是检验更长前缀的动机，不能作为“延长前缀会提升准确率”的结论。

限制在 QA3 特别集中：这份快照中的 Qwen 70/70 题和 GPT-OSS 60/60 题都到达 8-token 上限且当时还没有 EOS。新的配对结果会单独列出各题型，也会将初始前缀实际变长和未变长的题分组。

进一步检查固定开发集里 Qwen 的 **20 道 QA3 题**（5 个来源问题、各 4 种长度），第一步原问题的 20 个学生前缀都恰好在类似 `Before the kitchen the milk was in the` 的位置结束；后面的候选地点尚未生成，因此对应位置没有进入这一步蒸馏的时间步。这个检查不读取参考答案，见 [逐题记录](qa3_qwen_dev.json) 和[检查脚本](../../../experiments/anchored_short_verifier/audit_qa3_prefix.py)。前面各位置的 KL 仍比较完整词表，可能包含有用信号；该观察不等于证明它们没有信号，也不等于证明延长前缀一定提升准确率。

在这 20 题上，第一步的 Teacher KL 中位数为 **2.32 × 10⁻⁸**，两类读取参数的梯度范数中位数分别为 **9.59 × 10⁻⁹** 和 **8.36 × 10⁻⁸**；最终独立卡带相对同缓存零更新的生成 token 序列有 **0 / 20** 题发生变化。这些是首步日志和同缓存生成的描述，不能据此判断后续步骤的信号，也不能证明延长前缀会改善正确率，但它们提供了可检验的瓶颈：长前缀是否使目标位置及有效信号发生变化。

为了核对模型差异，我们进一步对原 OLMo 日志做了严格配对：仅保留完整原文、原始选块编号相同、且前 8 个学生 token 逐个解码后相同的 QA3 题。符合条件的 **9 题来自 5 个来源问题**；Qwen 与 OLMo 首步 KL 的中位数分别为 **1.72 × 10⁻⁸** 和 **0.0514**。两模型的词表、提示模板和参数化不同，KL 与梯度范数并非直接可比的能力分数，也不能用这组数据解释 OLMo 的全部涨点。这个对照表明需要按模型检查实际训练信号，而不能只照搬相同步数。[聚合和逐题记录](qa3_cross_backbone_dev.json) · [核对脚本](../../../experiments/anchored_short_verifier/audit_qa3_cross_backbone.py)。

同一 Qwen QA3 开发组里，按 Decision 分数选块的 Teacher 答对 **3 / 20**，同预算关联选块的 Teacher 答对 **7 / 20**；新增的 4 道正确答案来自 3 个来源问题，没有新增错误。两个 Teacher 均使用原通用格式要求；参考答案仅用于生成后评分。这支持同时验证证据选择和前缀长度，但 5 个来源问题不足以代表总体。[逐来源及逐题数据](qa3_linked_teacher_dev.json) · [统计脚本](../../../experiments/babilong_linked_selection/audit_qa3_teacher.py)。

新的对照保持原来的 10% 选块、Teacher、全文 Student、SD 目标与独立卡带，只把学生前缀上限由 8 改为 32。在相同参数状态下，如果前缀在 8 token 前产生 EOS，提高上限不会延长那次生成；后续优化仍可能改变生成路径。先对固定的 200 题进行配对比较，再将有效配置用于来源问题不重叠的留出题。

两组按源问题分开，但上表的历史快照包含其中一部分留出题，且其分组准确率已作为汇总被查看；因此这不是完全盲的留出评估。前缀长度候选由未结束的 token 日志提出，最终仍按配对结果报告，不把它当作已验证的提升。

[长短前缀对照检查脚本](../../../experiments/anchored_short_verifier/audit_qa3_rollout_comparison.py)会核对同题的选块、Teacher、零更新输出、练习和前 8 个学生 token，分别统计能匹配的 QA3 题中地点词是否进入了更长的蒸馏前缀、第一步梯度与最终 token 序列如何变化。两个长度的 KL 是分别在各自前缀位置上求平均，不能把它们的差直接当成相同位置的 KL 改善；准确率继续使用独立的配对评测报告。
