# Value 基底的跨视图检查

这项已完成的开发对照使用 BABILONG 40 题（10 个源问题，各四种长度），每模型逐题比较两种 rank-8 固定 Value 基底：一种由全文缓存中的选中位置计算，另一种由独立选中缓存计算。两组均在全文 Student 上用相同的选中 Teacher 和 SD 目标训练；最终读取独立选中缓存。Teacher、选块和零更新输出逐题核对一致。

| 模型 | 全文基底卡带 | 选中基底卡带 | 新对 / 新错 | 全文基底的选中 Value 能量 | 选中基底的选中 Value 能量 |
|---|---:|---:|---:|---:|---:|
| Qwen3-4B | 52.50% | 50.00% | 0 / 1 | 35.56% | 37.17% |
| GPT-OSS-20B | 60.00% | 60.00% | 0 / 0 | 43.69% | 46.61% |

能量列先对每题选中 Value 的最多 512 个位置计算其落入对应低秩基底的能量比例，再平均适配层和 KV 头，最后取 40 题中位数。选中基底覆盖的能量略高，但在这批题上没有带来答题收益；因此当前主实验继续使用 OLMo 的全文基底。能量覆盖并不衡量是否写入了正确事实，也不能单独解释训练效果。

两组卡带使用相同原问题格式和生成预算；Teacher 有额外的通用输出要求。参考答案只用于生成后的统一宽松词面评分。这是开发集上的小规模配对，全文缓存释放有记录，但当时的配对流程仍保留其他训练相关状态，因此不将它作为最终独立卡带显存的测量。

新的 [Value 对齐探针](../../../experiments/value_lr_physical/value_alignment_probe.py)会进一步比较**相同证据 token**在全文和独立选中缓存中的原始 Value、低秩坐标以及同一补丁实际写出的变化；它只做只读测量，尚未有真实模型结果。比对采用生产 KV 写入代码在采样位置执行，采样可能改变运算批次形状，因此不声称与全文缓存写入逐位相同。
