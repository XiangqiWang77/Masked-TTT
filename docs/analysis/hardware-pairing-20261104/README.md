# 同题比较中的 GPU 型号与生成差异

这份审计使用 2026-11-04 11:39:57 UTC 已保存的提示对齐开发集快照，以及对应的旧版两步 SD 日志；没有重新查询作业、运行模型或调用 API。它检查每道题两次运行的选块、Teacher 输出 token、已验证练习和同格式零更新输出 token 是否一致，题目答案和正确率不参与分组。

| 模型 | 两轮 GPU 型号 | 题数 | 上述任一配对条件不同 |
|---|---|---:|---:|
| Qwen3-4B | 相同 | 144 | 0 |
| Qwen3-4B | 不同 | 56 | 8 |
| GPT-OSS-20B | 相同 | 109 | 0 |
| GPT-OSS-20B | 不同 | 57 | 30 |

两种模型的选块在这些配对中都一致。Qwen 的跨型号 56 题中，Teacher token、练习和零更新 token 分别有 1、5、4 题不同；GPT 的跨型号 57 题分别有 6、25、1 题不同。一个题目可能同时计入多个差异。GPT 的日期字段在两轮都相同，Qwen 未记录该字段。这是 GPU 型号与配对差异之间的观察，不能仅据此断言硬件是唯一原因。

这些差异解释了为什么不能把两轮的全部结果视作严格的训练配置配对。后续对比应尽量在同一已加载模型、同一 GPU 和同一请求条件下执行，并分别核验选块、Teacher、练习及零更新输出；即使输出 token 一样，也不能假定完整概率分布一定相同。已有提示对齐报告会单独给出通过这些可观察一致性检查的配对样本。

聚合结果见 [summary.json](summary.json)，复核代码见 [audit_hardware_pairing.py](../../../experiments/prompt_alignment/audit_hardware_pairing.py)。输出不含题目、模型生成文本、参考答案或逐题 ID。

## 后续如何比较

[same_gpu_pair.py](../../../experiments/prompt_alignment/same_gpu_pair.py) 为后续调参提供单设备配对入口：同一个已加载的冻结模型顺序运行两套 SD 配置，共用原始请求和请求日期，并恢复运行前的随机状态。每个配置仍独立 prefill 全文和选中文本，独立训练、物化并释放缓存；因此它不会把一次运行的适配状态带入另一次。

工具只允许改变学习率、步数、学生前缀长度或训练时问题后缀这些 SD 设置；Teacher 指令、选择器和最终回答格式必须相同。它要求两个结果的选块、Teacher token、已验证练习和零更新回答逐项一致，且两个卡带都确实释放训练缓存，才返回这组配对。分布本身尚未逐元素比较，这些检查不能替代对其数值一致性的验证。入口不读取评测答案；评分由生成之后的评测流程完成。它使用进程局部诊断钩子，不应与同进程的其他请求并发。

该入口目前已通过 Qwen 和 GPT-OSS 的小模型测试；尚未用于新的真实 GPU 结果，也没有改变正在运行的任务或原始训练流程。
