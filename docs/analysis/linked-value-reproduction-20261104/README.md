# 在 GPT-OSS 上复现 OLMo 式 Query Cartridge

目标是用相同的推理方式，在 BABILONG 上复现 OLMo 对 ICL Teacher 的方法级提升。OLMo 原始 1,000 题结果为 Teacher **41.20%**、独立 Cartridge **44.60%**，提高 **3.40 个百分点**。Teacher 带通用输出要求，Cartridge 使用原问题格式；相同格式和选中缓存的另一轮配对中，零更新与训练后分别为 44.30% 和 44.50%，所以完整的 3.40 点不单独归因于参数更新。题目均采用 `answer_focused_lexical_v2` 宽松词面规则评分。

新的 GPT-OSS 候选固定以下配置：

- 复用已经缓存的 Decision API 分数，保留约 10% 的 chunk；其中 25% 的选块名额用于问题实体关联的候选，其余按分数选择。
- 冻结基础模型，以完整文档 KV 为学生，以独立 prefill 的选中文本 KV 为 Teacher。学生的短回答前缀作为两边共同条件，优化完整词表的 Teacher→Student KL。
- 仅在选中位置联合更新注意力读取增益与低秩 Value 修正；沿用 OLMo 的两步主问题更新和经过原文核验的可选自练习。增益学习率固定为 0.01，Value 学习率固定为 **0.001**。
- 将更新物化到独立选中 KV；释放全文 KV、源选中 KV 和训练状态后，使用原问题独立生成。预测或训练中不使用评测答案，不调用在线 API。

这个组合现已完成 200 题开发集：

| 全文 | 同缓存零更新 | ICL Teacher | 独立 Cartridge | 相对 Teacher | 相对零更新 |
|---:|---:|---:|---:|---:|---:|
| 53.50% | 61.00% | 62.00% | **62.50%** | **+0.50 点** | **+1.50 点** |

相对 Teacher，新答对 4 题、新答错 3 题；相对同原问题格式的零更新，新答对 6 题、新答错 3 题。与原 Value 学习率的历史运行比较，有 196 题通过选块、Teacher token、练习、零更新和初始前缀的严格可见配对，新答对 5 题、新答错 2 题，净增 1.53 点。这不是同 GPU 同时重跑的对照；Teacher 与正式卡带的回答格式也不同。[聚合数据](development.json)及[复核脚本](../../../experiments/linked_value/freeze_development.py)不包含题目或逐题 ID。

物理释放后，开发集卡带文档 KV 的逐题占比中位数为全文文档 KV 的 **20.81%**，即减少 **79.19%**；该比例不包含模型权重、问题／生成后缀或训练峰值。800 题的同类统计已接入现有小时报告，完成后可合并为 1,000 题统计。

配置来自两项此前完成的不同配对实验：原分数选块的 GPT 200 题开发集上，Value 学习率 0.001 相对同缓存零更新高 1.50 点；实体关联选块的 GPT 200 题上，ICL Teacher 为 62.00%，原问题格式的 Cartridge 为 61.00%。新的组合实验超过了三个同轮对照，已提交单 GPU 留出作业 **32011163**，继续评测其余 800 题；尚不能把开发集 0.50 点当作全量结果。

另外，一项已完成的同选块开发实验比较了 **2、4、8 步**（该实验使用 32-token 学生前缀，与新候选的 8-token 前缀不同）：

| 模型 | 题数 | ICL Teacher | 2 步 | 4 步 | 8 步 |
|---|---:|---:|---:|---:|---:|
| Qwen3-4B | 200 | 60.00% | 58.50% | 58.50% | 58.00% |
| GPT-OSS-20B | 200 | 62.00% | 61.50% | 60.50% | 61.00% |

各步数来自相同 Teacher、选块和优化轨迹；2、4 步为释放前配对解码，8 步为物理释放后的独立卡带解码。这组结果显示，单纯增加步数没有在这批题上带来收益；它不代表其他更新强度或 1,000 题的结果。

同一训练状态的 56 题精度对照中，Qwen 的 BF16 和 FP32 卡带均为 53.57%，GPT-OSS 分别为 39.29% 和 37.50%；FP32 卡带更大。两者还使用不同的注意力后端，因此目前继续以 BF16 为主，详见[配对精度报告](../precision-pilot-20261104/README.md)。

Qwen 当前 1,000 题中，即使事后知道答案、在 Teacher 和原格式训练后卡带两份输出之间理想选择，也只能达到 62.50%，比 Teacher 高 1.20 点。因此需要让更新或选块产生新的正确答案，而不是仅靠门控这两份固定输出；具体计算见[现有答案的选择空间](../qwen-fixed-output-bound-20261104/README.md)。

进一步对齐原始支持事实后，全文对、Teacher 错的 106 题中有 51 题漏选支持事实，55 题已完整覆盖标注事实。这将后续工作分为补全漏选与改善已选证据的使用两部分；详见[Qwen 支持事实分组](../qwen-support-partition-20261104/README.md)。

Qwen 开发集上的同预算问题词补选把完整支持事实覆盖由 157 / 200 提到 163 / 200，只改变 7 题的选块。该规则针对简单专名定位问题，在开发数据上设计；答题质量和跨来源表现需要新的模型评测。[开发集选块数据](../question-overlap-coverage-dev-20261104/README.md)。

计数题中，Qwen Teacher 的 58 个错误有 50 个报得偏多；100 题中仅 5 题产生经过核验的自练习。下一项无标签探针将比较自练习措辞，同时保留原文核验与原训练目标。[计数题诊断](../qwen-counting-error-20261104/README.md)。

开发集为 50 个来源问题的四种长度，共 **200 题**；同题记录全文、选中 KV 零更新、ICL Teacher 和独立 Cartridge，并与已有同选块基准严格配对。开发结果同时超过三个同轮对照，才自动提交 200 个不同来源问题的 **800 题**留出实验；最终报告将单列开发、留出与总计 1,000 题。另有两个留出来源问题在以往分析中被查看，且其他选块配置的全队列曾被分析，报告会保留这些信息。目标是留出集相对 Teacher 提高约 3 点，实际结果以实验为准。

实验使用一张高显存 GPU 和已有 JSON 分数，遵守最多 12 张 GPU 的共享上限，监控间隔一小时。代码与冻结协议在 [experiments/linked_value](../../../experiments/linked_value) 中。

独立的请求级卡带入口已在 Qwen3-4B 和 GPT-OSS-20B 的真实 B200 上通过合成请求的数值、梯度与缓存释放检查；这证明实现可运行，答题涨点仍以 BABILONG 评测为准。[验证结果](../request-local-gpu-preflight-20261104/README.md)。
