# Query Cartridge 的 Value 基底配对检查

## 问题

同一份文档分别进行全文 prefill 和选中片段 prefill，即使位置对应同一个片段，得到的 Value 表示也可能不同。原实现根据全文缓存的选中位置构造固定低秩基底，在全文 Student 上学习修正，再把修正应用到独立选中缓存。本检查比较一种候选初始化：从独立选中缓存构造这个固定基底。

## 保持一致的部分

两组都使用缓存的 Decision API 打分选择 10% 片段。两组的 Student 均在全文缓存上训练，Teacher 均来自独立选中片段；学习目标均为同一个 on-policy KL，联合更新同一组请求内注意力偏置和 Value 系数。没有增加全文到选中缓存的 KL，也没有在选中缓存上直接训练。基础模型和原始缓存冻结，独立 Cartridge 解码前释放全文缓存。

唯一变化是生成固定 Value 低秩基底所用的缓存：`document` 来自全文缓存，`selected` 来自独立选中缓存。基底不参与梯度更新，最终都将学到的系数作用在选中缓存上。

## 比较方法

每个模型使用同一批 40 个 BABILONG 开发案例，覆盖 10 个来源问题与四种长度；GPT-OSS-20B 和 Qwen3-4B 各做同题配对。报告 Whole、选中缓存零更新、ICL Teacher、两个基底的 Cartridge，以及配对的新答对和新答错。两个基底必须使用相同选块、Teacher token、零更新输出和问题格式才被视为有效配对。参考答案只在生成后用于相同的 loose 词面评分。

额外记录选中 Value 能量落入各低秩基底的比例，用来检查表示匹配；该比例本身不是回答正确率。开发集不能替代独立保留集。该变体的收益需要实验验证，不预先宣称提升。

默认值仍为 `value_basis_source=document`。小模型单元测试确认两种设置都只通过全文 SD 更新、原始缓存不变、预测前释放全文缓存；真实模型的 CUDA 注意力和配对结果在 GPU 作业中另行检查。
