# GPT-OSS-20B：Query Cartridges 的 BABILONG-1000 实验

## 研究问题

全文 KV 保留更多上下文，但回答时可能受到无关内容干扰；只保留选中证据更聚焦，也更紧凑，但选择可能漏掉回答所需的事实或关系。Query Cartridges 尝试把全文条件下训练出的请求内读取状态，应用到独立构建的选中证据缓存，在保持选中缓存紧凑性的同时改善证据使用。

这是一项需要实验检验的假设。全文缓存与选中缓存的差异不一定全是有用逻辑；自蒸馏也不自动保证最终选中缓存超过任一基线。

## 唯一运行的方法

1. 复用 Decision API 已保存的打分，对每题选择排名前 10% 的 chunk，按原文顺序拼接。
2. 冻结 GPT-OSS-20B，分别以完整文档和选中片段预填，得到独立的全文 KV 和选中 KV。Teacher 只读选中片段及问题。
3. Student 读完整文档。对选中位置的注意力偏置和低秩 Value 读取修正，以 Teacher 在 Student 自己生成的前缀上的分布为目标进行联合 SD；基础模型权重和原始缓存不更新。此实验的额外全文到证据 KL 权重固定为零。
4. 固定训练状态，将其应用于独立选中 KV 的新解码分支。完成需要全文的对照后，清理全文 KV 和训练引用，验证全文 KV 原始张量不再存活，再用选中缓存和原问题生成答案。

GPT-OSS 的练习题分词边界修复保留原方法的训练目标。若复用原换行仍不能严格匹配原缓存前缀，练习不会进入训练。

## 对照与报告

每题同一次运行报告：

- **KV Whole**：冻结模型使用全文 KV 回答。
- **KV Selective**：使用独立选中 KV、零更新、原问题回答。
- **ICL Teacher**：使用相同选中证据及 Teacher 的输出格式要求回答。
- **Query Cartridge**：全文条件下 SD 后，将状态应用到选中 KV，再用原问题生成。

KV Selective 与 Query Cartridge 使用相同的选块、问题后缀和生成长度，以便配对统计新答对和新答错。Teacher 的后缀额外包含输出要求；使用同一 Teacher 格式的选中零更新和训练后答案另行报告。评分统一使用既有的 answer-focused loose 词面规则，参考答案及支持事实标注只在生成后使用。

报告按整体、题型、上下文长度及支持事实覆盖分组，记录配对变化和 Cartridge／全文文档 KV 字节比，并区分原始 KV 存储、适配状态与实际 CUDA 分配量。为进行同题零更新对照，配对运行仍会保留原始选中 KV；该字节比不是单独 Cartridge 解码的实测峰值显存。分组是事后观察，不单独证明状态编码了被遗漏的关联。最终生成的图覆盖覆盖率对照、各题型的新增正确／错误和存储分布。

数据集包含 1000 题：8K、16K、32K、64K 各 250 题；十个题型各 100 题。1000 份已缓存打分与支持事实标注中的选块编号均通过一致性核验，不会产生新的 Decision API 调用。选块百分比是 chunk 数的比例，不等于实际显存百分比。

本实验使用一张 GPU，按原问题逐题保存结果；每次分配最长 6 小时，在原作业上续跑，累计 GPU 预算为 24 小时。报告在每次分配结束时更新，并额外每小时只读更新一次；监控不会提交其他方法。
