# GPT-OSS：将全文中的有用读取信号转入证据 Cartridge

## 目标

选中的原文证据使模型更聚焦；完整文档又可能提供跨片段的指代、时间和其他联系。我们希望保留前者的紧凑性，同时让 Cartridge 通过测试时训练吸收后者中对回答有用的部分。基础模型权重始终冻结，Decision API 的选块结果使用已经缓存的 JSON。

沿用 OLMo 实验的 ICL Teacher：Teacher 只读取选中的证据与原问题；Student 读取完整文档与同一个问题。可训练状态只作用于选中片段的读取路径，调整各片段的注意力分配和 value 读出。Teacher 输出的完整 token 分布提供自蒸馏信号，多个原文支持的小练习也可以训练同一份请求内状态。正式回答时，清除训练后缀，独立 prefill 选中证据并加载最终状态。

## 修复：在目标缓存上直接训练

原版的 Student 在全文缓存上训练，而最终 Cartridge 在重新构建的选中证据缓存上运行。两者读取环境不同，训练时的收益不一定能直接转移。因此这里增加一项跨缓存一致性：让全文和选中证据两条读取路径共享同一份可训练状态，在同一问题和同一生成前缀下，让选中缓存的预测接近全文缓存的预测。全文路径的目标分布在该项中停止梯度。

令 $S_D^\phi$ 表示全文 Student，$S_E^\phi$ 表示选中证据 Student，$T_E$ 表示冻结的 ICL Teacher。对选中 Student 自己生成的前缀，训练目标为

$$
L(\phi)=D_{\mathrm{KL}}(T_E\|S_D^\phi)
+\lambda D_{\mathrm{KL}}(\operatorname{stopgrad}(S_D^\phi)\|S_E^\phi).
$$

第一项使用原版的 Student 前缀，第二项使用选中 Student 的前缀；每一项内部两边使用相同的前缀。两个分支引用同一组可训练参数，文档 KV 和模型权重不被覆盖。若 $\lambda=0$，计算退回原版流程；正的 $\lambda$ 则直接训练最终要使用的选中缓存。参数更新后重新输入问题生成答案，不给 Student 塞入 Teacher 的完整答案。

## 如何理解补丁

可以把这份共享的请求内读取状态理解为一个补丁：它尝试将全文读取中有帮助的预测信号转移到证据 Cartridge 上，而不要求 Cartridge 重建全文。它并非严格计算 $M_D-M_E$：全文和选中证据是在不同上下文下生成的缓存，全文信号也可能包含干扰。是否学到有用的全局关系，必须由同题实验验证。

## 实验

先在固定开发集上比较原版 $\lambda=0$ 与 $\lambda=0.25,0.75$，复用同一组题、同一份选块、同一个模型以及统一的评分。记录 Teacher、零更新 Cartridge、训练后 Cartridge、全文更新前后，以及每题新增答对和新增答错。然后固定配置，在未用于选择参数的题上复测；参考答案只用于生成后的评测，不进入选块或训练。目标是在 GPT-OSS-20B 上获得相对于 ICL Teacher 稳定的性能提升。
