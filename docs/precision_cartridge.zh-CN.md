# 保留 Value 修正的物化精度

## 动机

当前训练得到的 Value 修正通常很小。若先把修正转成 BF16，再与幅度更大的原始 Value 相加，舍入可能使一部分修正无法进入最终缓存。这与最终答案是否改善是两个不同的问题，但它是可以直接测量的物化误差。

在固定的 GPT-OSS 开发快照中，同一批 86 道题、同一 Teacher 和同一选中缓存的采样测量如下：

| Value 学习率 | 写回后改变的分量比例中位数 | 相对理想修正的平方误差中位数 |
|---|---:|---:|
| 0.0001 | 24.38% | 62.61% |
| 0.0003 | 54.91% | 21.65% |
| 0.0010 | 82.31% | 2.42% |

这里的误差以修正本身的能量为分母，不是完整 KV 缓存的误差，也不是准确率损失。测量只针对选中缓存中采样的 Value。三个学习率的实际答题结果仍需配对验证。

## 实验方案

`experiments/precision_cartridge/materialization.py` 保持原来的全文 Student、选中 Teacher、训练目标和训练参数不变。构造独立 Cartridge 时，在 float32 中计算并物化 \(V_E+\Delta V_E\)，避免将小修正先舍入并加回 BF16 原值。Key 偏置仍按原方法物化；未选中的全文 KV 仍在独立回答前释放。

这个实验使用 float32 Value 缓存和支持混合输入的因果注意力计算。它比原 BF16 缓存占用更多存储，注意力实现也可能更慢；两者均应实测。实验上下文只适用于单请求，不应与其他并发请求共用同一进程。

## 验证

CPU 测试覆盖 Qwen3 和 GPT-OSS 的 BF16 小模型，核对 Teacher、全文输出及训练梯度不变，检查物化后全文 KV、选中源 KV 和训练状态均被释放，并比较 float32 修正与理想值。`real_model_probe.py` 可在已经加载的真实模型上做同样的成对执行与内存检查。

该修改是数值精度候选方案；只有在真实模型和同题准确率对照完成后，才能判断它对回答质量是否有帮助。
